# Operating AgentRoom v0.2

## Local configuration

Node >=22.12, pinned pnpm, and `wrangler login` for deployment. No application secrets are configured: room secrets are generated by clients. Never place invitations or Authorization headers into GitHub Actions secrets, tracked fixtures, issues or logs. `.wrangler/` and generated `dist/` are ignored. A locally saved live smoke invitation uses file mode 0600 under `.wrangler/` and contains synthetic test data only.

`wrangler.jsonc` creates one new SQLite Durable Object class through `new_sqlite_classes`. Existing namespaces/rooms survive subsequent script deployments. Application tables initialize only during explicit room creation. Future schema migrations must be additive and versioned; never replace the namespace to deploy a UI change. V2 requires a private R2 bucket agentroom-v2-files bound as FILES. Its 31-day lifecycle rule is a secondary cleanup safeguard. Never expose a public bucket URL or attach unrelated existing buckets.

Build dependencies are pinned in package.json/pnpm-lock.yaml. Miniflare is pinned to the exact version bundled by Wrangler so integration tests use the same Workers runtime generation. Python is a test-only independent crypto implementation.

## Cumulative deployment preflight

1. Fetch origin; resolve canonical `main`. Inspect `git status`, branches, `git worktree list`, open AgentRoom task state and the current live/last-accepted behavior. Coordinate any overlaps. Do not touch another task's files.
2. Integrate every accepted relevant change on main. Compare source/content/routes/protocol, not just current changed files. Retain `/`, `/security`, `/r/:id`, `/agent`, favicon/static assets and the agreed modals. V2 intentionally retires `/v1/*` and `/protocol/v1`, replaces them with `/v2/*` and `/protocol/v2`, and adds `/r/:id/agent`. Do not migrate or prematurely delete old rooms. A newly initialized project has no prior accepted surface; subsequent releases do.
3. Push main. `pnpm run deploy` rejects a dirty checkout, another branch, or a main divergent from a fresh fetch. It runs type/API/crypto/browser checks, rechecks remote main, deploys and runs live smoke.
4. `pnpm smoke` checks the previously accepted v2 synthetic room (when the local state is available), public routes, private headers, API misses and a fresh two-process encrypted exchange. If prior smoke data has expired, explicitly inspect its TTL before archiving only that owned local fixture and creating a new baseline. Never silently ignore missing accepted live data.
5. Re-run desktop/mobile browser tests against live with `AGENTROOM_TEST_URL=https://agentroom-v0.hagen-hoferichter.workers.dev pnpm test:e2e`. Respect creation rate limits when repeating quickly.
6. Record canonical SHA, Worker version, live checks, platform status and worktree ownership/cleanup. A feature branch, preview or commit alone is not delivery.

## Releases

Build from verified main. Create a version tag pointing to that exact commit and attach `dist/agentroom.mjs` and `dist/SHA256SUMS` to a GitHub release. Verify the downloaded artifact hash against both release and local build. Never replace an existing version's artifacts: fixes need a new version and updated public protocol reference.

No automatic deployment of unreviewed PR branches. CI has read-only repository permissions and no Cloudflare token. Initial deployment uses the owner's existing local OAuth session. Release publication and deployment are separate actions; neither guarantees actual provider compatibility.

## Logs, lifecycle and monitoring

Application logging and Cloudflare Workers observability are disabled in config. Do not enable full request/body/header logs during debugging. Use aggregate hosting request/error/usage metrics only; redact URLs and secrets before recording failures. Investigate 5xx, repeated 429 and abnormal room-creation volume. Account plan and limits determine cost; IP limits are approximate per-location, not a global billing cap. Review current Cloudflare usage/spending controls before expanding beyond the test deployment.

Expiry is enforced in every room/file request. The alarm deletes the R2 room prefix before SQLite storage; failures retain cleanup state and retry after 60 seconds. The bucket lifecycle expires objects after 31 days as a safeguard. Alarms are at-least-once; cleanup handles repeats and delayed execution. Expired-but-not-cleaned access returns 410; a deleted/missing room returns 404. Provider recovery/backups may outlive deletion. Do not market immediate physical erasure.

## Abuse and incidents

Collect only room IDs in abuse reports; never ask for the private fragment. Use authenticated Cloudflare Durable Object administration to inspect technical metadata or remove affected room data. Keep public admin/deletion endpoints out of the app. Validate the account's administrative deletion path before a broad pilot; the V0 test release is not the 10–20-pair public pilot milestone.

On a suspected webclient compromise, stop advertising the site, preserve technical evidence without secrets, and publish an advisory through repository release/security tooling. Assume exposed room links are compromised; V0 has no rotation/revocation. Do not silently roll back to a stale source snapshot: prepare and test a cumulative fix on main. Do not delete/recreate a namespace to repair application code.

## V2 release cut

No old-client compatibility is maintained. Old local smoke fixtures remain archived under .wrangler; the live smoke checks their explicit v2 unsupported-protocol response. New v2 rooms use accepted-smoke-v2.local. Old release assets remain immutable. Profiles must not be committed or copied into room contents. No R2 plaintext or public object URLs. Test fixtures/fault-relay.mjs is test-only and must never replace the production entry.
